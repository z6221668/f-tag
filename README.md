# f-tag

f-tag 是一个 Chrome / Edge 用户标记插件。给论坛账号设置等级、标签和备注后，再次遇到这个账号时，用户名旁会显示之前的标记。

所有记录都保存在本机。插件没有账号系统，也不会上传标签、备注或浏览记录。

## 能做什么

- 每个用户设置一个等级，描述标签可以多选。
- 保存标记原因、来源链接和标记时间。
- 在页面中添加或修改标记，同一账号出现多次时同步显示。
- 识别新加载的回复、评论和用户链接。
- 在设置页搜索、编辑或移除记录，支持撤销最近一次用户标记操作。
- 设置站点白名单，白名单中的网站及其子域名不再检查。
- 导入、导出 JSON 备份。导入前保存本地恢复快照。

等级默认是“一级 · 留意”“二级 · 低质量”“三级 · 避雷”，名称和颜色都可以改。等级和标签分别保存，不会同时给一个用户设置多个等级。

## 支持的站点

| 站点                        | 账号识别方式                                  |
| --------------------------- | --------------------------------------------- |
| 知乎                        | `/people/<账号>`、`/org/<账号>`               |
| V2EX                        | `/member/<用户名>`                            |
| NodeSeek                    | `/space/<数字 ID>`                            |
| LINUX DO                    | 用户卡片中的 `/u/<用户名>` 链接               |
| Chiphell、吾爱破解、Hostloc | Discuz 用户 UID，包括查询参数和伪静态主页链接 |

其他站点默认识别 `/member/`、`/users/`、`/user/`、`/u/` 下的账号链接，也可以添加自定义规则。

这些适配器已经有账号解析和页面测试，但部分网站的登录态、移动版或特殊页面仍需验证。浏览器内部页面、扩展商店、匿名用户、没有账号链接的用户名和封闭 Shadow DOM 内的内容无法识别。详细范围见 [验收记录](docs/RELEASE.md)。

## 安装

当前提供开发版安装包，尚未在浏览器商店上架。

1. 下载源码，或解压已有的发布 ZIP。源码仓库不包含 `dist`，需要打包时运行 `npm run package`。
2. Chrome 打开 `chrome://extensions`，Edge 打开 `edge://extensions`。
3. 开启开发者模式，选择“加载已解压的扩展程序”。
4. 使用源码时选择 `extension` 目录；使用发布包时选择解压后包含 `manifest.json` 的目录。
5. 刷新需要使用插件的网页。

更新开发版后，先在扩展管理页点击 f-tag 的“重新加载”，再刷新网页。只刷新网页不会更新已经缓存的后台代码。

## 使用

点击用户名旁的 `Tag`，选择等级或标签，然后保存。默认只显示等级、紧凑的标签列表和保存按钮。备注、来源和标签管理收在“更多操作”中；来源默认填入当前页面地址，可以修改或清空。

要取消某个用户的标记，在等级下拉框中选择“清除标签”，再保存。此操作会移除该用户的等级、标签和备注，保留标签库；保存后可以撤销。

点击标签旁的“+ 新建”即可展开名称和颜色输入。创建后会立即存入所有用户共用的标签库，并选中该标签；还需要保存标记，才会应用于当前用户。

取消勾选标签后保存，只会移除当前用户上的这个标签。要删除标签本身，展开“更多操作”，进入“管理标签库”，点击标签旁的“删除标签”并确认；这会移除所有用户上的该标签，删除前会保存恢复快照。标签超过 8 个时会显示搜索框。

未保存的用户修改会在关闭弹窗时提示确认。放弃用户修改不会撤销已经完成的标签库新建或删除。

保存后会出现“撤销”按钮。也可以从浏览器工具栏打开 f-tag，进入“标签与记录”管理已有记录。多个页面同时编辑同一用户时，过期的编辑器会提示重新打开，不会覆盖新记录。

如果一个站点没有出现按钮，先检查插件是否启用、站点是否在白名单中，再确认用户名链接是否符合支持的格式。

## 自定义规则

在设置页展开“自定义规则（JSON）”。例如，论坛用户名链接是：

```html
<a class="username" href="/profile/alice">Alice</a>
```

对应规则：

```json
[
  {
    "host": "forum.example.com",
    "selector": "a.username",
    "prefix": "/profile/"
  }
]
```

- `host`：当前页面的完整域名，不带协议、端口和路径。
- `selector`：选择用户名链接的 CSS 选择器，选中的元素必须是 `<a>`。
- `prefix`：账号前面的固定路径，以 `/` 开头和结尾。

每个域名只能有一条规则，多个域名放在同一个数组里。保存会替换整个规则列表。内置站点适配器优先，自定义规则不支持 `user.php?uid=123` 一类查询参数账号。

已经存过标记后，不要随意改账号路径前缀。路径前缀属于用户标识的一部分，修改后可能匹配不到旧记录。

## 备份与恢复

导出文件包含等级、标签、用户记录、备注、来源和站点设置。快照和撤销记录不包含在导出文件中。

- 旧版本备份可以导入新版；未支持站点的记录会保留。
- 更高插件版本或更高格式版本的备份会被拒绝，并提示升级。
- 0.1 / 0.2 的多个等级会迁移为最高等级，原来的选择保留在备注里。旧记录没有时间信息时显示为未知。
- NodeSeek、LINUX DO、Chiphell、吾爱破解、Hostloc 的 `www` 与主域名记录会合并；不同账号、不同站点和其他子域名保持独立。
- 升级迁移、导入和删除标签前会保存一份本地恢复快照。恢复快照时，当前记录也会保存为新的快照。
- 快照只保留最近一份。最近一次用户标记保存或移除可以撤销；下一次标记操作会替换撤销记录。

Chrome、Edge 和不同浏览器配置各自保存数据，需要通过导入导出迁移。卸载插件或清理扩展数据会删除记录和快照，建议定期导出文件备份。

## 开发

需要 Node.js 20+ 和 Python 3.10+。插件运行时没有第三方依赖；Prettier 仅用于开发时检查代码格式。

```sh
npm ci
npm run check
npm test
npm run test:performance
npm run package
```

打包产物位于 `dist/f-tag-<版本>.zip`。测试、文档、开发工具和本地记录不会进入发布包。

启动页面测试服务：

```sh
python3 tools/preview.py
```

- `/tests/stress-fixture.html`：1 万条记录和 600 个用户链接的长页面测试。
- `/tests/fixture.html`：标记、动态内容、白名单、页面恢复和编辑冲突测试。
- `/preview/options?test=1`：设置页、旧备份、导入确认、恢复和撤销测试。
- `/tests/site-fixture.html?site=nodeseek.com`：站点测试。参数还支持 `linux.do`、`chiphell.com`、`52pojie.cn`、`hostloc.com`。
- `/preview/options`、`/preview/popup`：界面预览。
- `/tests/native-fixture.html`：实际安装插件后的注入检查，不使用 Chrome API 替身。

以上地址使用 `http://127.0.0.1:8768`。页面测试使用测试存储，真实扩展测试使用独立浏览器配置，测试数据不包含个人备份。

批量运行页面测试：

```sh
python3 tools/browser-fixtures.py --browser /path/to/chrome-headless-shell
```

修改代码后可以运行 `npm run format`。GitHub Actions 配置了格式检查、单元测试、性能基准和打包检查。

## 代码结构

```text
extension/
  core.js          数据结构、验证、迁移和备份版本规则
  repository.js    串行写入、恢复快照和撤销
  background.js    消息入口与操作权限检查
  adapters.js      站点适配注册与分发
  adapters/        各站点账号识别
  editor.js        页面和设置页共用的编辑表单
  content.js       页面检查、标签显示与页面生命周期
  client.js        设置页和弹出面板的消息请求
  options.*        数据管理与备份
  popup.*          当前站点开关
```

新增站点和修改数据结构时的约定见 [开发说明](docs/DEVELOPMENT.md)。

图标使用本项目提供的原图，位于 `assets/icon-original.png`。`python3 tools/icons.py` 可以重新生成各尺寸图标，需要 Pillow；macOS 也可以使用系统的 sips。已有图标可直接用于打包。
