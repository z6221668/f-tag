# 开发说明

## 模块职责

`core.js` 定义数据结构、字段验证、迁移和备份协议，不读取网站数据，也不直接写入存储。

`repository.js` 是唯一持久化入口。服务线程中的一个队列串行处理读、校验、写，避免多个页面互相覆盖。`background.js` 负责检查消息来源和允许的操作。

`editor.js` 被网页弹出面板和设置页共用。`content.js` 只处理页面识别、显示、观察和生命周期，使用账号索引查找记录。

## 用户与等级

主键为 `(site, id)`，不能用昵称、头像或个人描述作为主键。

| 站点            | ID 格式                         |
| --------------- | ------------------------------- |
| 知乎            | `people/<token>`、`org/<token>` |
| V2EX            | `member/<小写用户名>`           |
| NodeSeek        | `space/<数字 UID>`              |
| LINUX DO        | `u/<用户名>`，保留原始大小写    |
| Discuz 适配站点 | `uid/<数字 UID>`                |
| 通用站点        | 不带开头 `/` 的账号路径         |

每个用户的 `levelId` 为空或引用一个等级，`tagIds` 可以引用多个描述标签。三个等级的顺序固定，名称与颜色可编辑。备注上限为 2,000 字符，来源链接只接受无账号密码的 HTTP/HTTPS 地址。

`createdAt` 和 `updatedAt` 由写入入口维护。旧记录的未知日期使用 `null`。同一条记录的编辑通过 `expectedRecord` 检查，冲突时要求重新打开编辑器。

Chrome 消息和存储可能改变对象键顺序。比较记录和判断是否需要迁移时，必须使用 `stableStringify` / `recordToken`，不能直接比较 `JSON.stringify` 结果。回归测试会模拟存储返回的键排序。

`revision` 是本地状态的递增修订号。导入、恢复和撤销都必须产生新修订号，网页和设置页不接受更旧的状态响应。

## 迁移与备份

当前数据 `schemaVersion=2`，备份 `formatVersion=2`。备份另有 `appVersion`，其版本高于当前插件时一律拒绝导入。

版本 1 的迁移规则：

1. 将默认的 `level-1/2/3` 标签移到等级定义，保留已修改的名称和颜色。
2. 用户选了多个等级时保留最高等级，在备注中记录原来的选择。
3. 其他标签保留为描述标签。
4. 旧记录的备注和来源为空，未知时间为 `null`。
5. 合并内置站点的 www 账号别名；描述标签取并集，等级取最高，备注和其他来源保留。

NodeSeek、LINUX DO、Chiphell、吾爱破解、Hostloc 的 www 主机名归一化为主域名，其他子域名不合并。未知站点记录不得依据适配器名单删除。新增站点时沿用已发行的 ID 格式；改变身份格式必须先提供明确迁移和测试。

导入在设置页检查结构和 CSS 选择器，后台再次验证格式和插件版本。确认期间数据发生变化时，拒绝覆盖。

## 恢复与撤销

升级迁移、导入、删除标签前，先写入恢复快照，再写入新状态。快照写入失败时不得继续替换记录。恢复时把当前状态保存为新的快照，仅保留最近一份。

用户标记保存和移除产生一个带令牌的撤销记录。只能撤销对应的最近一次操作。导入、恢复、删除标签会清除用户撤销记录，避免引用已不存在的标签。

存储空间不足时应返回明确错误。快照、当前状态和撤销记录均占用浏览器的本地配额；数量验证上限不是容量保证。导出文件不包括内部快照和撤销记录。

## 新增站点

每个站点单独注册适配器：

```js
UserTagsAdapters.register({
  name: 'Example Forum',
  domain: 'forum.example.com',
  preserveHost: true,
  selector: 'a.username[href*="/member/"]',
  resolve(url) {
    const match = url.pathname.match(/^\/member\/([^/]+)\/?$/);
    return match ? 'member/' + match[1] : null;
  },
});
```

先检查真实作者、回复和账号主页结构，再添加文件。选择器必须选中用户名的 `<a>` 链接，解析器只接受明确的账号 URL。

加载入口包括 `manifest.json` 的 content scripts、`background.js` 的 `importScripts`、`popup.html` 和测试页面。共用解析器要放在使用它的适配器前面。测试会检查入口的一致性。

`discuz.js` 提供查询参数和伪静态主页解析，但仅对独立注册的论坛启用。通用识别不能用来声称所有论坛均已适配。

## 页面行为

MutationObserver 收集变化区域后去抖扫描。插入自己的 UI 时暂停观察，避免循环触发。隐藏页面、禁用插件和进入白名单时停止观察；页面返回时重新启动。

单页导航、账号链接替换、姓名变化和浏览器页面缓存恢复都有页面测试。标签使用封闭 Shadow DOM 隔离网站样式；同一显示内容不重复重建 DOM。

输入文本使用 `textContent`，不能把昵称、标签、备注或备份字段写进 `innerHTML`。来源链接单独验证协议。扩展页面禁止网络连接，不加载远程代码。

## 检查

```sh
npm ci
npm run check
npm test
npm run test:performance
npm run package
```

`check` 包括格式、JavaScript 语法、加载入口、图标尺寸和权限配置。测试关注迁移、并发、失败后的数据保护以及真实 Chrome 存储的键顺序，不为单纯的 DOM 工具函数建立重复测试。

页面测试和实际扩展测试见 README。原生测试必须使用独立浏览器配置；开发版修改后需重新加载扩展，后台脚本的缓存不会因网页刷新而自动更新。
